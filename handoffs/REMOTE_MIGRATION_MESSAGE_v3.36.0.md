## Rollback

Never reset or rewrite shared history. Revert a committed migration with `git revert`; before commit, restore only the recorded migration path set from the saved baseline commit. Re-run the baseline tests and wake-up, and record `ROLLED_BACK` or `HOLD`. Published tags are never moved. The kit writes to a member at its apply step and through that member's own session. Its tools also write at the output paths passed to them; keeping those paths outside the members' repositories is an operator rule, not enforced by the tool. At the supervisor, the kit's tools are removed by reverting the commit that added them. That does not remove the release target file, records file or committed durable batch archives (`migration/<slug>/batchN/`) in your supervisor repository. The live batch folders, packet roots, stages and confirmation clones stay outside the repository under the sibling run root named in setup; at B13, copy only the durable lists, results and their `runs.jsonl`, evidence to keep and the B13 record into those archives, never packet roots, stages or confirmation clones. The clones the suite check and the packet rehearsal's reference run leave under `~/.cache/aget-suite-at-commit/` also remain.
