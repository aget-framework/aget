# v3.31.0 — Ship What Was Already Built

**Prepared**: 2026-08-15 · **Type**: minor · **State**: RELEASED (published 2026-08-15)

> v3.31 promotes five verification instruments that had been working privately for weeks into the

## Why this release

The cycle began as a routine weekly release and turned into a measurement. Over one release week the
framework's own management seat produced 37 new scripts; canonical received none of them. Ten were
framework-general, and every one was absent from the public repository.

The bottleneck was not authorship. It was promotion: nothing moved a working instrument from the seat
that wrote it to the framework that ships it, and nothing detected the omission. What the public release
carried, cycle after cycle, was the residue.

v3.31 ships five of those instruments. That is the whole of the feature content, and it is deliberately
modest — these are tools that already worked, already had tests, and were held back only by the absence
of a promotion step.

## What ships

### Added — five verification instruments, each with its test

| Instrument | What it answers |
|---|---|
| `check_skill_route_contract` | Do the `/aget-*` routes that skills name resolve to skills that exist? |
| `check_deprecation_removals` | Has a registered deprecation passed its removal version with the row still open? |
| `release_cadence_gap` | What is the current release-gap reading against the cadence policy? |
| `validate_changelogs` | Does every release repository carry a CHANGELOG entry for the target version? |
| `validate_initiative_proposal` | Does an initiative proposal satisfy its conformance criteria? |

Skill descriptions were also made routable, so every shipped skill is selectable by description.

### Fixed

- `study_topic`'s ontology tier never opened the vocabulary, silently suppressing matches.
- The audit-pairing gate was satisfiable by a write rather than an audit.
- The close-gate guard now covers closure-class headings and table-row status.
- The actuator-census corpus predicate no longer gates on filename *and* extension.
- Declared verification sources made host- and topology-independent.
- **A validator reported `PASS` having inspected nothing.** Unresolvable repositories were skipped and
  dropped from both numerator and denominator, so the success branch was reachable with zero files
  opened. Zero and partial coverage now fail. Its test suite previously asserted only that a constant
  had 14 entries and never called the function, which is why a four-line defect shipped.
- Three portability defects in promoted tests that passed at the producing seat and failed at a
  consumer: a fixture directory assumed to exist, a live-registry assertion that failed on absence
  rather than skipping, and an instance-scoped regression asserting one named skill on disk.

### Changed

- Stamp-masquerade gap half closed, with the remaining half documented rather than silently carried.
- v3.30 post-release disclosure, citation, and handoff repairs.

## Known limitations — stated, not discovered later

Three of the five promoted instruments carry defects that are disclosed rather than fixed in this
release. None misleads the way the zero-denominator defect did, but a consumer should know:

| Instrument | Limitation |
|---|---|
| `check_deprecation_removals` | The deprecation registry it reads is not shipped, so it reports `UNAVAILABLE` here. Its `--advisory` flag does not force exit 0 as its help text states — an early return precedes the advisory branch |
| `release_cadence_gap` | Returns exit 1 both for "cadence cap breached" and for "could not locate the repository", so a red result is not self-explaining |
| `validate_initiative_proposal` | Cannot reach a full pass in this repository: two of its checks require a proposals index that is not shipped. A missing environment is scored against the proposal |

`check_export_resolvability` was **held back** from this release: three of its tests assert on a specific
ontology's *content* rather than its presence, making them instance-coupled rather than portable.

## What this release does not claim

The promotion gap this release illustrates is not closed by it. A separate, governed project covers the
inventory and remediation of private content across the public repositories, and that work is neither
started nor claimed here. Nothing in v3.31 should be read as evidence that surface is clean.
