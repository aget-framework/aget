## Why this release

Two facts, both measured rather than asserted.

**A gate nobody runs is not a gate.** v3.27.0's own release-quality score records its release battery as
*"never run this cycle"*. The battery then ran a week **after** that release shipped and reported two
blocking failures. A control that reports blockers after the ship has no leverage over anything.

**And one of those gates could not pass.** Pre-release validation ran the full contract suite under a
60-second timeout against a suite that took **528 seconds** — 81% of it inside three tests that each re-ran
the entire release battery. A BLOCKING check was structurally unpassable, so its failure had become
background noise.

The pattern under both: **controls were invoked by the party they constrain.**

## What changes for you

### 1. Release acts are now gated at the moment they happen

A `PreToolUse` hook fires on `git tag`, `git push --tags` and `git push --follow-tags`. It runs the release
battery and the release-quality gate, and **exits non-zero if either fails** — without anyone choosing to
run them.

**What you will notice**: a tag or tag-push may be refused with `🚫 RELEASE GATE FIRING GUARD`. The message
names every failing condition.

**To proceed**: fix the failures, or **record an explicit principal-authorized override, with a written
reason, in your session file**. Silently skipping is not available — that is the point.

*(Deliberately stated in full rather than cited. Lesson IDs are **not unique across seats** — the same
`LNNN` names a different lesson in a different agent's corpus, so a citation here would resolve to the
wrong thing at your seat. Everything this file asks of you is spelled out.)*

**Precision guard**: the hook triggers only when a command *begins with* the release act. Commit messages,
heredocs and `echo`/`grep` text that merely *mention* a tag pass through. (An earlier iteration blocked its
own commit; those cases are now standing regression tests.)

### 2. A release-quality score can no longer certify itself

The Phase 7.1.5 score must declare an **independent verification leg** that resolves:

```
- **independence**: type=headless-audit; verifier=<seat>; evidence=<path|#issue>; date=YYYY-MM-DD
```

Checked, not trusted: the verifier must resolve in FLEET_STATE, must not be the producing seat, the evidence
must exist **and carry findings prose** (a bare verdict is not a landed leg), and the score must record that
the reply was held **claims-under-test**.

⚠ **Known limitation, stated so you do not rely on it**: the check tests *non-identity with the producer*
and nothing about the verifier's **stake**. A seat with an interest in the outcome passes it. Choose a
disinterested verifier yourself — the check cannot do it for you.

### 3. Your controls now record when they fire

Any gate refusal appends to `.aget/logs/control_firings.jsonl`:

```json
{"ts":"…","control":"…","subject":"v3.28.0","action":"BLOCKED","hook_event":"PreToolUse","seat":"…"}
```

`hook_event: PreToolUse` means the control fired **unbidden**; `ABSENT` means someone ran it by hand. The
field is *recorded*, never asserted — the distinction is the evidence.

**Please do not delete this file.** It is how the framework learns that a control blocked something real at
a seat other than the one that built it.

### 4. Triage freshness is a measured SLO

An untriaged-age rollup with a second verb: two consecutive rollups with no triage between them is itself
reported, so *measuring* the queue can no longer substitute for *working* it.

### 5. Test-requirement traceability has a floor that moves

The long-standing 80% figure was, in its own source comment, a *pilot aspiration*. It had never been met
(actual: 39%) and became a permanent tag-blocker the moment the suite was enforced. It is replaced by a
**ratified floor of 39%, rising 5 points per minor release**, derived from `version.json` rather than typed
by hand. It blocks **regression** instead of blocking everything.

## Upgrade guide

**Estimated time**: 10–15 minutes per seat.

1. **Pull and bump.** Sync your framework copy, then set your `.aget/version.json` `aget_version` and your
   `AGENTS.md` `@aget-version` line to `3.28.0`.
2. **Take the hook.** Copy `.claude/hooks/release_gate_firing_guard.sh` and register it under
   `PreToolUse` in `.claude/settings.json`. **Seats that never tag releases may skip this** — it is inert
   for non-release commands, but there is no reason to carry it.
3. **Run your health check and contract suite.** Expect them to pass. If the suite is slow, see below.
4. **Do not delete** `.aget/logs/control_firings.jsonl` if one appears.

### If a gate blocks you

Read the message — it names the failing condition. Two legitimate paths: fix it, or record a
principal-authorized override with a written reason. **A third path is not provided**, deliberately.

### If your contract suite runs long

Check for tests that invoke a release guard against your real repository root. Three such tests here held
430 of 528 seconds because each re-ran the full battery. Pointing them at a stub battery preserved every
assertion and cut the file from 435s to under 1s.

## Rollback

Nothing in this release changes data formats or artifact schemas. To roll back: restore your previous
`version.json` and `AGENTS.md` version strings and unregister the hook from `.claude/settings.json`. The
firing ledger is append-only and harmless if left in place.

## Cycle findings — what this release *learned*

*Recorded separately from scope on purpose. The section above is what we committed to build; this is what
executing it surfaced. Several of these are more consequential than the scope.*

- **Every defect this cycle produced was a missing *edge*, not a missing *node*.** Orphaned script → nothing
  `invokes` it. Dangling path → nothing it `resolves-to`. Gate ordering fault → no `depends-on`. Issue done
  but open → no `closed-by`. Threshold never met → no `has-ever-passed`. The artifacts all existed and
  looked like progress; the relationships did not.
- **The proof is a counter-example.** The one artifact relationship this framework models *and checks* — a
  skill-reliance manifest, `declared ↔ on disk` — stands at **52/52, zero errors**. Everywhere the edge is
  unmodelled, a single day surfaced 60+ breaks.
- **This release reproduced its own root cause.** Of three Tier-1 controls, two were wired to an actuator and
  one shipped **built and unwired** — in the cycle themed *make the gates fire*, undetected by four gates, an
  independent critic and ninety recorded rulings. Knowing the root was not sufficient to stop doing it.
- **Three phase-ordering faults** were found by *executing* gates rather than reading them: a readiness gate
  requiring a validator only a later phase can satisfy; a tag gate requiring an artifact a post-release phase
  produces; a consistency check requiring bumps scheduled three gates later.
- **A release's metadata dates had never been bumped.** v3.27.0 shipped carrying dates seven days stale — a
  citable artifact asserting a modification date preceding its own release.
- **A research tool advertised a surface it never searched**, so every study reported zero specifications.
  That is *manufactured absence*: worse than an omission, because it supplies false evidence of
  non-existence.

**What we would tell a seat adopting this release**: when you build a control, the work is not finished at
the file. It is finished when something runs it without anyone choosing to.
