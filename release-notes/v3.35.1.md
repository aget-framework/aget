# AGET v3.35.1 — Weekly train: what landed on main since 3.35.0

**Release date**: 2026-10-04
**Release type**: patch

Release candidate prepared 2026-10-03 for publication on 2026-10-04. This document does not assert publication, installation or downstream acceptance.

## Why a weekly train

[AGET](https://w3id.org/aget/vocab#AGET_Framework) now releases every weekend. Each train ships whatever has met its own definition of done that week; a large feature that is not done rides a later train instead of holding the others back. v3.35.1 is the first train. It ships what reached `main` after 3.35.0: six content pull requests (#108 to #113), each with all of its checks successful at merge (8 of 8, including the seven checks `main` requires today; the required-check configuration at each merge time is not recoverable), and this release's own files. (The sixteen commits after the 3.35.0 tag also include #107, the merge that published 3.35.0 itself.) It adds no other code.

The migration kit is not in this release. It keeps the version 3.36.0 and ships on the first train it is done for.

### A public decision log

`governance/DECISION_LOG.md` records, in plain language, why the framework's rulings were made, so anyone can check why AGET is as it is. Deliberation stays private; the reasons are published. A fresh-context review after publication found no private identifiers, and five details that said more than the reasons needed were removed. Seven requirements files were refreshed from the principal's requirements ledger at the same time, including a requirement that states this openness position.

### Grounded term display form (CAP-VOC-006)

The vocabulary specification moves to v1.18.0. CAP-VOC-006 says how a term grounded in a named register is highlighted in prose: as a term-shaped code span holding the entry's preferred label, or an alias that points to exactly one entry. A term with no entry is never highlighted; a wanted term is written in italics, as a visible absence. Paths, commands, file names and identifiers in code spans are outside the rule. Verification rows V-VOCAB-011 to V-VOCAB-016 define how it is checked; their automated checks are still owed. The older prose rules are scoped to the specification's own register.

The same change corrects one identity definition. The specification defined `Aget_Instance` twice, inconsistently; it is now a kind of `Aget_Agent` (the concrete agent created from a template, which a fleet collects), no longer a kind of `Aget_AI_System`, and a checkout of it on a host is a working copy, not a second instance. Documents that relied on the older hierarchy should be read against the new definition.

This is a prose rule; it changes nothing an [Aget](https://w3id.org/aget/vocab#Aget_Agent) runs.

### `study_topic` and suppressed results

When the relevance floor hid every hit, `study_topic` printed "novel topic", turning a score boundary into an absence claim. It now reports how many hits were suppressed and how to see them (`--no-floor`). Both polarities are tested. The fix ships in the core repository and, byte-identical, in all 13 templates.

### Smaller changes

- **CLI support matrix**: the Antigravity terminal agent holds levels L1 and L2 (`agy --print` is non-interactive); L3 is unproven. The Gemini CLI retirement is dated from the vendor notice. The evidence checker declares Antigravity's instruction surface.
- **Referent registry**: ontology concept links resolve only for published concepts, so the registry now says `partial`, with a dated measurement, and defines what `partial` means.
- **Corrections and amendments**: the 3.35.0 corrections record opens with four rows. Two handoff records carry in-record amendments for files edited after their release, with the released digests intact; the corrected-manifest test accepts such an amendment and still fails an unamended edit.
- **Licence**: `template-analyst-aget`, `template-architect-aget`, `template-executive-aget`, `template-operator-aget`, `template-researcher-aget` and `template-reviewer-aget` now ship the Apache 2.0 `LICENSE` file their README declares.

## Upgrading

Nothing breaks and nothing is removed. A receiving Aget that takes this release gets the `study_topic` fix. The other changes are documents and one specification rule. See `handoffs/RELEASE_HANDOFF_v3.35.1.md` and `handoffs/REMOTE_MIGRATION_MESSAGE_v3.35.1.md`.

## Known limitations

- This patch carries one specification addition, CAP-VOC-006, a prose display rule. It adds no behaviour a receiving Aget runs.
- The 13 templates still ship the close-authorization guard at its unrepaired 3.34.0 version: a close recorded "under principal GO" is misclassified. The repair is in core only. Apply the workaround in `handoffs/CORRECTIONS_v3.35.0.md`, row 4; propagation to the templates is not in this release.
- Publication, installation and receiver acceptance are separate facts and need separate evidence.

## Rollback

Return to the `v3.35.0` tag. No state migrates, so rollback restores the previous files only. Published tags are never moved.
