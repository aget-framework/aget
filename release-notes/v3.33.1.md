# v3.33.1 — Receiver-visible integrity

**Target release date**: 2026-08-30 · **Type**: non-breaking patch release
**Artifact state**: prepared corrective candidate; tag identity, publication, and receiver acceptance
remain separate predicates

## Why this patch exists

The complete v3.33.0 tag and Release transaction succeeded, but the blocking post-release check did not.
The immutable core handoff lacked the required external-fleet context, the document-processor template
lacked governed routing and write-scope sections, and the mutable organization homepage still advertised
v3.32.0. A public tag cannot be repaired in place, so the release train moves forward to v3.33.1.

This patch preserves the original v3.33.0 payloads as historical evidence. It does not edit, move, delete,
or reinterpret them.

## What changes

### Complete receiver context

`handoffs/RELEASE_HANDOFF_v3.33.1.md` includes the required `Context for External Fleets` section. It
explains which evidence is producer-owned, which decisions stay receiver-owned, and why publication is
not installation or acceptance. The matching deployment specification and remote migration message are
available at the same immutable core tag.

### Governed document-template behavior

The document-processor template adds substantive Skill Routing and Write Scope sections. The routing
table maps document-processing tasks to existing template capabilities; the boundary names both allowed
project outputs and prohibited source overwrite, out-of-workspace writes, credential access, and
unauthorized external publication. This satisfies the governing template
AGENTS specification rather than inserting a marker solely to appease the post-release regex.

The template's other pre-existing configuration findings are not silently absorbed or called fixed.
They remain outside this narrow integrity correction.

### Coherent public identity and discovery

All thirteen templates carry the v3.33.1 version, migration-history, changelog, and README surfaces. Only
the document-processor template adds behavioral governance content; the other twelve packages are
version-coherence releases. The organization homepage advances its complete governed surface set to
v3.33.1 with a curated current-release entry.

`docs/VERSION_HISTORY.md` now records both v3.33.0 and v3.33.1. Historical release surfaces are never
waived merely because a newer patch becomes current.

## Verification contract

Before any tag, the release requires exact changed-path registers, complete core and template suites,
document-template Tier-1 configuration evidence, homepage generator conformance, independent exact-head
review, configured PR checks, and received-state tree equality after merge.

After publication, the composed release gate, standalone post-release validator, published-body checker,
homepage checker, fourteen tag/Release identities, and computed v3.33.1 definition of done must all pass.
A real downstream receiver receipt remains required before release closure.

## Compatibility and rollback

There are no intentional breaking changes. Existing v3.33.0 installations may remain pinned; new
upgrades should select v3.33.1 after publication and follow its tag-bound handoff. If receiver validation
fails, restore the saved pre-upgrade commit or prior pin, preserve the evidence, and keep adoption on
hold. Never move a public version tag.
