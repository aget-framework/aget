# AGET v3.37.0 — Receiver fixes and runner pin

Prepared for publication on 2026-10-17. Publication is evidenced by the annotated tag `v3.37.0` and its GitHub Release object. Read the tag's peeled commit with `git rev-parse 'v3.37.0^{commit}'`; a file inside the tagged commit cannot name it.
Template tags, hosted continuous integration and receiver acceptance require separate verification.

## What changes

The previous release is v3.36.0. This release repairs receiver migration failures, adds receiver adoption checks, pins continuous integration to Ubuntu 24.04, excludes compiled caches from template payloads, and makes wind-down health timeouts visible.

### Receiver adoption kit

The supervisor installs the kit from the pinned core tree; it remains separate from template payloads. `sops/SOP_fleet_migration.md` v1.11.0 describes the receiver adoption policy and the skew check before the supervisor's upgrade. Part B runs baseline sessions (B6), applies the approved files (B7), runs the halt check (B7a), then starts migration sessions (B8). Suite and smoke checks precede push authority (B9) and push (B10).

The halt check compares root `AGENTS.md` and `CLAUDE.md` against the recorded pre-apply commit. It checks allowed changed lines, identity lines in order, size, mirror content and file/link transitions. Default allowed changes are whole-line version and canonical-specification pins, including the templates' long reliance form. The supervisor's declarations in its own `.aget/adoption_policy.json` extend the defaults for every member it checks. Regex size, input length and evaluation time are bounded; an unavailable check stops the batch.

Run the halt check for every applied member. CONTINUE is exit 0, HALT is exit 1, and UNAVAILABLE is exit 2. HALT and UNAVAILABLE both stop the batch. Read the printed or JSON verdict of every tool; a tool's exit 0 alone does not establish migration completion.

### Template payload and wind-down checks

The payload gates reject case-insensitive `__pycache__` path components and `.pyc`/`.pyo` suffixes at every depth, including unchanged tracked cache files. A deletion of such a file is allowed. The standalone offline commands and exit codes are documented in `docs/RELEASE_PAYLOAD_GATE.md`. The cross-template gate requires the template repositories and tags; a clean core tree alone does not establish clean template tags.

Set `AGET_WIND_DOWN_HEALTH_TIMEOUT` to an integer from 1 through 3600 seconds (default 120). Invalid values visibly fall back to 120. On macOS/Linux the timeout terminates the health process group; pipe draining is bounded to five additional seconds. Descendants that leave that group may survive. TIMEOUT records an incomplete health observation; it does not by itself fail session close. See `docs/protocols/WIND_DOWN_PROTOCOL.md`.

## Known limitations and disclosures

- The pre-tag payload gate reads only the committed subtree under its working directory or `--cwd`; run it from the repository root or pass that root as `--cwd`. The producer payload gate has no automatic caller in the release path; run it by hand as the runbook says in `docs/RELEASE_PAYLOAD_GATE.md`. An observation-free health check exits 0 with `clean_close` true; read the Health Gate line, which reports UNKNOWN. One test checks only the screen text, without checking the exit code or `clean_close`.
- The test-body witness can report a body as complete when a skip is injected into the test body's own frame (for example by a conftest trace hook or an alarm signal), and when a decorator implemented as a plain closure converts a body failure into a skip. Conversely, skips inside `subTest` bodies are reported as not complete even though the body ran. These cases can misclassify completion; a complete result does not establish that skipped behavior passed.
- The kit changes only the root `@aget-version` line; it does not update `@aget-canonical-specs`. Verify the version against 3.37.0 and record the unchanged specification pin. Change that specification pin in a separate reviewed commit outside the kit batch and after-run window, then verify it against the intended release. Editing it inside that window fails the protected-file checks.
- The kit halt_check checks only root AGENTS.md/CLAUDE.md; a near-match-all receiver declaration can pass validation; pins are not bound to the target release. Nested instructions, local overrides and `.claude/rules` are outside that check. Inspect those separately, verify the version against 3.37.0, and record the unchanged specification pin for its separate reviewed update outside the after-run window.
- Scope evidence survives retirement in the permanent, append-only `data/scope_archive.jsonl`, beside the ledgers. The gate checks every ledger in the data folder and its archive anchor (row count and rolling hash). It refuses a missing, shortened or mismatched archive, a moved anchor, and symlinked ledger or archive paths. Commit the archive and ledgers together; never delete or edit the archive.
- A scope instruction that was never recorded cannot be recognised — type launches as separate prompts. The ledgers and archive are one trust domain: consistent edits of both, or rolling back the whole data folder, can remove the evidence. The kit locates its code directory by resolving symlinks; a replaced code directory pointing at another kit's data is outside the protection. On case-insensitive disks, seed with the exact-case path.
- Old-format scope records block launches until retired with `python3 scripts/migration_kit/record_authority.py --session <id> --retire-scope <aget> --principal-line "GO supervisor - the old scope override for <aget> no longer applies"`. The principal must type that whole fixed confirmation form (using the configured prefix if it differs from `GO supervisor - `); the tool archives the full entry before removing it. Retired scope quotes still cannot authorize launch. Before launches resume, run `python3 scripts/migration_kit/record_authority.py --archive-ledger data/<ledger>/records.json` once for every previous ledger in the data folder with scope history, and seed active scope history too. The gate names unseeded ledgers and refuses launches until all are seeded. Use exact-case paths on case-insensitive disks.
- Template symlink containment: a tracked symlink pointing outside a template is kept. Cache filtering does not prove every retained link target stays within the template; inspect these links before instantiation or deployment.
- Ubuntu 26.04 qualification not yet done. The Ubuntu 24.04 runner pin is containment, and hosted validation of the new action majors remains separate from this offline build.
- The migration kit's test-body witness requires Python 3.12+ (`sys.monitoring`). On Python 3.10/3.11, a run that needs it remains INCONCLUSIVE. Reporting a body skip does not prove the skipped behavior passed.
- Prior kit limitations remain, including fixed older release labels, payload lists and validation commands. A readable successful GitHub CI result on the exact published commit is still needed for covered receiver repositories. A local-only rehearsal does not supply it.
