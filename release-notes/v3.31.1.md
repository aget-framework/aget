# AGET v3.31.1 — Receiver-Safe Close Gates

**Release date**: 2026-08-18  
**Release type**: patch correction  
**Supersedes for close-gate migration**: v3.31.0

## Why this patch exists

The first public-main repair placed related close-gate files together, but publication alone did not
prove that a remote receiver could acquire one complete, compatible package and observe the same verdict
through every supported channel. The lifecycle implementation was still described as instance-owned,
the default schema path depended on a sibling checkout, human output could disagree with JSON, invalid
accounting could be written before rejection, and the added behavior lacked an end-to-end public oracle.

v3.31.1 closes that chain. It treats commit publication, immutable release identity, installability,
behavioral acceptance, delivery, and downstream adoption as separate predicates.

## Corrected package

- `scripts/close_gate_lifecycle.py` is framework-owned and ships beside `close_gate_check.py`.
- The default project-plan specification resolves inside the same checkout; the documented environment
  override remains available.
- Human and JSON renderers consume one decision. Orphan and non-waivable accounting failures block both.
- Human output includes independence and value warnings and no longer prints a false “no signals” claim
  after accounted unfinished work.
- Closure-table writes validate and reconcile in memory, then use atomic replacement. A rejected mutation
  preserves the original bytes.
- The close-project skill uses disposition-aware semantics and no longer carries the contradictory
  “refuse any unchecked gate” rule.
- `tests/test_close_gate_receiver_contract.py` exercises channel, phase, disposition, error, mutation,
  and clean-room topology dimensions through the public CLI.

## Distribution and verification

The supported acquisition point is the immutable `v3.31.1` tag, not an untagged main-branch commit.
`handoffs/DELIVERED_FILES_v3.31.1.yaml` binds the ordered package members and their SHA-256 digests.
`DEPLOYMENT_SPEC_v3.31.1.yaml` and `handoffs/REMOTE_MIGRATION_MESSAGE_v3.31.1.md` define receiver checks.

The manager-suite requirement-reference measurement is 42.956% against a 54% release floor. The
principal authorized a one-release exception because the release-critical subset measures 60.772% and
continued delay withholds the supported close-gate repair from dependent supervisors. The complete
scope, method, limitation, remediation deadline, and no-renewal consequence are public in
`handoffs/TRACEABILITY_EXCEPTION_v3.31.1.md`. No behavioral or receiver check is waived.

Public CI is the independent structural acceptance leg for implementation conformance. It does not prove
that a particular downstream supervisor fetched, installed, or adopted the release. Receivers must record
their own tag identity, digest verification, clean-room test result, and migration V-test.

## Compatibility and rollback

This patch does not migrate or rewrite project plans automatically. Existing instance-owned extensions
remain receiver-owned. If the close-gate correction fails at the receiving seat, restore the pre-upgrade
checkout, preserve the failing fixture and receipt, and remain parked; do not reinterpret v3.31.0 as the
accepted correction package.
