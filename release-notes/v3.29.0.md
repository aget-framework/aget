# v3.29.0 — Repair release truth and reduce principal decision work

**Prepared**: 2026-08-01 · **Type**: minor · **State**: PRE-PUSH

> This document describes the verified local release candidate. v3.29.0 is not public until Gate 3
> independently verifies remote commits, tags, GitHub Releases, and live surfaces.

## Why this release

v3.29 repairs the gap between an artifact existing and its control or decision consequence actually being
reachable. It also makes the principal-facing release decision consultable from one generated view and
exposes a small AGET support bundle through Codex-native discovery.

## What changed

- **Instruction reach through decomposition (H-29-003)**: root configuration size and semantic reach are
  separate checks. The framework manager root is reduced from 86,098 to 35,819 bytes while its full
  preimage remains archived; the advisor template is 29,381 bytes. Required bootstrap, write-boundary,
  gate-discipline, self-amendment, and nested-scope controls pass.
- **Claude/Codex structural-control contract (H-29-012)**: the supported-client set is exactly Claude Code
  and Codex CLI. Both are evaluated for applicability, trust/permission boundary, positive block, negative
  control, and denial without side effects. The Codex implementation is an isolated POC; project trust is
  not silently changed.
- **One release-decision view (H-29-013)**: one generated view renders the locked six-family roster,
  principal rulings, supported clients, delivery behavior, deadline, Goal boundary, and requirements-ledger
  reach. Acceptance is exactly one view, zero contradictions, zero omissions, and zero manual joins.
  The generator runs in a framework-manager seat containing the governed source set; the bare public core
  is its distribution point, not a substitute source set.
- **Distribution evidence that cannot collapse (H-29-016)**: producer, distribution point, received state,
  and downstream behavior are independent predicates. Manager-side `tag_release.py` now invokes the
  blocking battery inside the actuator before its first tag/push/release operation. `[instance-only per L600]`
- **Codex-native support bundle (H-29-018)**: `.agents/skills/` exposes `aget-wake-up`,
  `aget-study-topic`, and `aget-save-state`. Explicit `.claude/skills` fallback remains recovery rather
  than native-discovery PASS. Literal `/aget-*` compatibility is deferred to v3.30.
- **Truthful study-topic research (H-29-022)**: purpose globs now affect ranking; sessions retain an
  explicit recency bound; scripts/tests/hooks are opt-in; specs/inbox/sessions/instruments render as detail
  tiers; and the omission banner names the work repository and web as outside the instrument.

## Upgrade guide

1. Pin the v3.29.0 core/template tag and update `.aget/version.json` plus `AGENTS.md` to `3.29.0`.
2. Preserve existing instance-owned extensions and local governance. Do not overwrite `scripts/*_ext.py`.
3. For Codex, confirm `.agents/skills/{aget-wake-up,aget-study-topic,aget-save-state}/SKILL.md` resolves.
   Do not change `.codex/config.toml` or `trust_level` as part of this upgrade.
4. Run `python3 scripts/study_topic.py --topic release --purpose pre-release --include-sessions --json`
   and confirm `search_contract` states the purpose, recency, and external omissions.
5. Run the receiving seat's normal health and contract tests and compare with its pre-upgrade baseline.

## Breaking changes

None. Existing Claude skills remain present. The new Codex discovery paths are additive. Purpose weighting
changes result ordering only when `--purpose` or a configured default purpose supplies priority areas.

## Rollback

Revert the v3.29 release commit or restore the v3.28 tag. Remove the three `.agents/skills` exposure links,
restore the prior `study_topic.py`, and restore prior version metadata. No data schema migration or
destructive state conversion occurs.

## Known boundaries

- Producer-side native discovery is not downstream delivery. `GOAL-V329-DELIVERED` remains active until a
  downstream v3.29 Codex seat discovers, invokes, and recovers during ordinary use.
- The requirements reach census still reports historical bare-R collisions/unqualified headings; the one
  view renders that debt and uses qualified `v329-release:R1-R3` rather than claiming the debt is gone.
- Health warnings for standing SOP/citation debt remain warnings; release-blocking errors are zero.

## Monitoring and feedback

Report public defects through `aget-framework/aget`. Release coordination and downstream delivery evidence
remain governed separately from this public artifact.
