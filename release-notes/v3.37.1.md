# AGET v3.37.1 — Supervisors can adopt a release on the day it ships

**Release date**: 2026-11-04
**Release type**: patch (on v3.37.0)

## Why this patch

In v3.37.0 the migration kit for supervisors waits seven days after a release before it says a supervisor may adopt it, unless the supervisor sets its own wait. That seven-day default was a proposal that was never approved; the ruled default is no wait, because a published release is already public. v3.37.0 disclosed this and gave a workaround (`handoffs/CORRECTIONS_v3.37.0.md`, row 2). This patch fixes it.

## What changes

- `scripts/migration_kit/adoption_policy.py`: the default `min_release_age_days` is 0, and `--show` reports it as a ruled default.
- `sops/SOP_fleet_migration.md`: the example policy and the defaults table say 0.
- `tests/migration_kit/`: failing-first controls for the default, the SOP text and the defaults table.

Nothing else changes. A wait you set in `AGET_ADOPTION_MIN_RELEASE_AGE_DAYS` or `.aget/adoption_policy.json` still applies; so do the patch rule (`--fixes-me`) and the Wave-1 soak.

## Upgrading

If you set `min_release_age_days` to 0 as the v3.37.0 workaround, you can keep it or remove it; the result is the same. If you copied the kit into your supervisor repository, copy `scripts/migration_kit/` again from a core clone at `v3.37.1`.

## Tests

`tests/migration_kit/test_fwk_r132_release_age.py` and `test_fwk_r132_release_age_text.py` fail if the seven-day default comes back in the code or the procedure.

## Known limitations

- The supervisor template's quick start asks you to set your own `domain`, and one template test then expects `supervision`. Tracked separately; not changed here.
- The installer check is automated; a person may follow the steps differently.

## Rollback

Set `min_release_age_days` in your policy file to the wait you want, or stay on v3.37.0 with the documented workaround.
